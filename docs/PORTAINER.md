# Portainer

Portainer's admin account is auto-provisioned on first start from `PORTAINER_ADMIN_PASSWORD` in `.env` (via the `--admin-password-file` CLI flag, pointed at a single-use secret file generated by `install.sh`), so the manual setup-token wizard is skipped.

Open `https://portainer.<HOSTNAME_FQDN>` and sign in directly with username `admin` and `PORTAINER_ADMIN_PASSWORD` from `.env`. The local Docker environment (the same host Portainer is running on, via the mounted `/var/run/docker.sock`) is detected and managed automatically; there is no Environment Wizard to complete.

If the credentials in `.env` don't work, Portainer may have fallen back to its normal setup-token flow (for example, if `portainer/secrets/admin_password` wasn't readable when the container first started, or `portainer_data` already contained an admin from an older install). In that case, retrieve the token and complete the wizard once:

```bash
docker logs portainer 2>&1 | grep setup_token
```

`PORTAINER_ADMIN_PASSWORD` must be at least 12 characters; `install.sh` checks this and refuses to continue otherwise, since Portainer would otherwise reject it silently and leave the instance uninitialized.

Like `--admin-password-file` itself, this only takes effect the first time the admin account is created. Changing `PORTAINER_ADMIN_PASSWORD` in `.env` and re-running `install.sh` does **not** change an already-provisioned admin's password — update it from Portainer's own UI (**My account**), or remove the `portainer_data` volume for a full reset if you want the new value in `.env` to take effect again.
